# RTX 4090 composition profile — 2026-07-21

This is a measured lower-bound profile of RISC Zero receipt composition, not a
production EVM-block benchmark. Both guests fit one 65,536-cycle segment: the
cold guest hashes a fixed template and the suffix guest verifies the cold
receipt assumption and hashes a fixed hot suffix.

## Results

| Stage | Same-process warmed path | Fresh process with cold cache |
| --- | ---: | ---: |
| Load and verify cached cold receipt | — | 27.790 ms |
| Cold composite proof, paid once | 940.312 ms | 0 ms |
| Cold composite to succinct, paid once | 534.666 ms | 0 ms |
| Hot suffix composite proof | 324.827 ms | 933.589 ms |
| Suffix lift/join plus resolve cold assumption | 881.387 ms | 1,026.554 ms |
| Hot proof plus resolve | **1,206.214 ms** | **1,960.143 ms** |

The cold run took 3.707 seconds wall-clock including CUDA/process startup,
receipt verification, serialization, and writes. The fresh-process cache-hit
run took 2.703 seconds wall-clock. A persistent prover is the relevant service
shape; the 1.206-second row is the observed same-process warm lower bound.

The cached cold succinct receipt is 223,290 bytes. The resolved final succinct
receipt is 223,418 bytes and has a 96-byte journal. The cold proof is not
executed or generated again, but every final proof still pays a recursive
`resolve` that verifies and folds the cached cold succinct receipt.

## Ethereum-seal blocker (since diagnosed and fixed — not a standing limitation)

> This run used the unpatched crates.io stack (`risc0-sys` 1.5.0,
> `risc0-groth16-sys` 0.1.0, `sppark` 0.1.15). The abort below was root-caused
> two days later — sppark ABI mismatch against the 0.1.12 the Groth16 setup
> assets were built with, the 48-byte coefficient layout, two CUDA
> stream-ordering races, and missing bounds checks on rounded zeroization
> launches — and fixed by the vendored patches in the `[patch.crates-io]` block
> of `zkvm/Cargo.toml`; see the "Proof reliability correction" section of
> `docs/V5-READINESS-2026-07-23.md`. This spike now mirrors that patch
> table in its own `Cargo.toml`, so the leg below is not expected to reproduce
> on the current dependency set. It has not been re-run: the spike has no
> consumer, so no L1 verification gas measurement was ever taken here.

Two identical CUDA Groth16 attempts failed before producing a seal. Both
containers exited `139`, were not OOM-killed, and reported:

```text
sppark_error: cudaStreamSynchronize ... failed: "an illegal memory access was encountered"
```

The attempts failed after 11.361 and 12.417 seconds wall-clock. Graph loading
took 0.925/0.914 seconds and typed-graph witness calculation took 1.617/1.667
seconds. Because no Groth16 receipt or Ethereum router seal was emitted, this
profile establishes successful resolved-succinct composition only. It provides
no L1 verification gas measurement.

summary are stored locally under
`test-results/v4-gpu-composition/risc0-composition-v3-20260721-0940/`.
